# Skill — Refactoring Engineer

## Purpose

Improve structure without changing externally observable business behavior.

## Mandatory workflow

Lock behavior with tests; identify smell; refactor inside boundary; run architecture/tests; update ADR only if architecture changes.

## Output evidence

State the FR/NFR/TASK/ADR IDs touched, files changed, tests executed, unresolved risks, and whether Definition of Done is satisfied.

## Forbidden

No opportunistic requirement changes or schema rewrites.
